# Projects

A small collection of static web projects by Vitaliy, published with GitHub Pages.

**Project index:** [utkin-vitaliy.github.io/projects](https://utkin-vitaliy.github.io/projects/)

## Projects

### Offday

A static Canadian work-calendar reference with separate regional employment, federal employment, regional public-service, and federal public-service views. Covers all 10 provinces and 3 territories, with English, French, and Russian interface text.

- **Open the app:** [Offday](https://utkin-vitaliy.github.io/projects/canada-days/)
- **Project folder:** [`canada-days/`](canada-days/)
- **Project documentation:** [`canada-days/README.md`](canada-days/README.md)

### Capsule Shelf

A personal Nespresso Original and Vertuo capsule inventory and recipe collection. Track quantities, favorites, restock thresholds, tasting notes, and recipes in English, French, or Russian. Personal settings stay in the user's browser and can be backed up to or restored from a JSON file, or synced through the user's Google Drive.

- **Open the app:** [Capsule Shelf](https://utkin-vitaliy.github.io/projects/capsule-shelf/)
- **Project folder:** [`capsule-shelf/`](capsule-shelf/)
- **Project documentation:** [`capsule-shelf/README.md`](capsule-shelf/README.md)

## Publishing

GitHub Pages serves the repository's static project index at `/projects/` and projects in their own subfolders, such as `/projects/capsule-shelf/` and `/projects/canada-days/`. The [GitHub Actions Pages workflow](.github/workflows/pages.yml) tests both apps, builds Capsule Shelf, publishes both projects, and prepares the root index. Push to `main` or run the workflow manually from the repository's Actions tab to publish.

## Adding a project

1. Add the static site's source to a new top-level folder.
2. Configure its build to use the matching GitHub Pages base path, such as `/projects/new-project/`.
3. Add a build and publish step to the Pages workflow and copy the output to `pages-artifact/new-project/`.
4. Add a link and short description to the root project index generated by that workflow.
5. Keep secrets, credentials, and private user data out of the repository. Anything committed here is public.

### Development Team release checklist

Apply this checklist to each app on the static site during design, implementation, and QA. For existing apps, record missing items in the project backlog or next change plan and address them as changes are scheduled.

- [ ] **Project README.** Keep a `README.md` in the app's own root with its purpose, local run and publishing instructions, main features, and known limitations.
- [ ] **App icons.** Provide a favicon, an Apple touch icon for iOS and iPadOS, and a web app manifest with suitable Android home screen icons. Use artwork appropriate to the app. In QA, check the favicon, manifest, and icon URLs under the app's published subpath and verify the home screen icon on both platforms.
- [ ] **Feedback.** Place a visible, localized “Leave feedback” link or button in the app footer. Use [Capsule Shelf's footer](capsule-shelf/src/App.tsx) as the reference for placement and styling. When the repository and issue template are available, open the GitHub feedback form in a new tab and indicate when submissions are public. In QA, verify the control on mobile and desktop, with keyboard navigation, in each supported language, and check that it opens the intended form.
- [ ] **Language order.** When an app has a language selector, show the supported languages in this order: English, French, Russian. Keep this order consistent across desktop and mobile layouts.
