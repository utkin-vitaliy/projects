# GitHub Pages статическая публикация

## Цель

Сделать Capsule Shelf статическим React/Vite приложением, которое можно собирать и публиковать через GitHub Pages. Остатки, избранное и заметки остаются в браузерном хранилище; резервные копии переносятся кнопками скачивания и загрузки.

## Границы

- Убрать Node API и файловый JSON из runtime и локального запуска.
- Сохранить одноразовое чтение старого ключа `capsule-shelf:inventory:v1` и перенести его в актуальный ключ браузера.
- Собирать Vite assets с базовым путём, подходящим для project Pages.
- Добавить GitHub Actions workflow для сборки и публикации содержимого `dist`.
- Не помещать личные остатки в Git.
- Не менять видимость репозитория в рамках реализации кода. Владелец переключил `utkin-vitaliy/projects` в публичный во время работы.
- В репозитории `projects` приложение размещено в `capsule-shelf/`; Pages workflow должен находиться в корне репозитория и публиковать только `capsule-shelf/dist`.

## Подходы

1. **GitHub Actions и project Pages (выбранный).** Workflow соберёт Vite приложение и развернёт `dist`; подходит к существующему проекту и не требует сервера.
2. **Публикация из ветки с готовыми файлами.** Проще для чистого HTML, но здесь требует коммитить сгенерированные assets и вручную поддерживать их актуальность.
3. **Оставить Node API.** Не подходит к GitHub Pages, поскольку Pages обслуживает только статические файлы.

## Решения реализации

- `npm run dev` запускает только Vite.
- `useInventory` читает и пишет browser localStorage; если ключ `v2` отсутствует, однократно импортирует старый `v1` ключ. API/file migration больше нет.
- `vite.config.ts` вычисляет `base` из `GITHUB_REPOSITORY` при Pages build и использует `/` локально.
- Workflow запускается на `main` и вручную, собирает проект из `capsule-shelf/`, использует официальный Pages artifact/deploy flow и минимальные permissions.
- В README описать запуск, browser-only хранение, ручной backup/restore и локальную сборку.

## Проверка

- Компонентные тесты подтверждают сохранение и восстановление данных из localStorage, включая заметки и неизвестные архивные ID.
- `npm test -- --run`, `npm run build` и `git diff --check` проходят.
- Предпросмотр сборки проверяется с project base path.

## Ограничение публикации

GitHub подтвердил, что `utkin-vitaliy/projects` теперь публичный. В публичном репозитории находится прежний личный файл `capsule-shelf/data/inventory.json`; Pages artifact будет собираться только из `capsule-shelf/dist`, поэтому этот файл не попадёт на сайт, но остаётся доступен в репозитории и его истории. GitHub Pages сайты общедоступны.
